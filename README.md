# SimpleAI — Local Hybrid RAG Chatbot

A self-hosted **Retrieval-Augmented Generation (RAG)** API built with FastAPI. Upload a PDF, then ask questions about it. Answers are generated by a **local LLM via [Ollama](https://ollama.com/)** and are strictly grounded in the document — if the answer isn't in the source, the assistant says so instead of guessing.

The retrieval pipeline is intentionally non-trivial: it combines **dense vector search** (ChromaDB) with **sparse keyword search** (BM25), fuses the two with **Reciprocal Rank Fusion (RRF)**, and finally **reranks** the candidates with a cross-encoder before passing context to the LLM.

> Status: learning / work-in-progress project. Expect debug `print` statements and experimentation in the code.

## How it works

```
                ┌─────────────┐
  PDF upload ─► │  clean text │ ─► chunk ─► embed (Ollama) ─► ChromaDB
                └─────────────┘            └─ tokenize ─────► BM25 index
                                                                  │
  Question ─► rewrite (LLM) ─┬─► vector search (ChromaDB) ──┐     │
                             └─► keyword search (BM25) ◄─────┴─────┘
                                          │
                                          ▼
                            Reciprocal Rank Fusion (RRF)
                                          │
                                          ▼
                          Cross-Encoder rerank (top candidates)
                                          │
                                          ▼
                       Grounded answer generation (Ollama / llama3)
```

### Ingestion (`POST /greet/upload`)
1. Extract text from the PDF (`pypdf`).
2. Clean it — strip page numbers, dotted placeholders, broken unicode/words (`services/cleaning_text.py`).
3. Split into overlapping, sentence-aware chunks (`services/chunking.py`).
4. Build a **BM25** index over the chunks (`database/bm25_store.py`).
5. Embed each chunk with Ollama (`mxbai-embed-large`) and store vectors in **ChromaDB** (`database/chroma_client.py`).

### Question answering (`POST /greet/ask`)
1. **Query rewriting** — the LLM expands the question into 2–3 search variants.
2. **Vector retrieval** — semantic search over ChromaDB, with controlled neighbor expansion and keyword-overlap scoring.
3. **Keyword retrieval** — BM25 over the same chunks.
4. **Fusion** — both result sets are merged via Reciprocal Rank Fusion, then deduplicated.
5. **Reranking** — a cross-encoder (`cross-encoder/ms-marco-MiniLM-L-6-v2`) rescores the top candidates.
6. **Answer generation** — `llama3` answers using *only* the retrieved context, returning the answer plus source snippets.

## Tech stack

| Concern            | Choice                                          |
|--------------------|-------------------------------------------------|
| API framework      | FastAPI + Uvicorn                               |
| LLM & embeddings   | Ollama (`llama3`, `mxbai-embed-large`)          |
| Vector store       | ChromaDB (persistent, on disk)                  |
| Keyword search     | `rank_bm25` (BM25Okapi)                          |
| Reranking          | `sentence-transformers` CrossEncoder            |
| PDF parsing        | `pypdf`                                          |

## Prerequisites

- **Python 3.9**
- **[Ollama](https://ollama.com/)** running locally with the required models pulled:
  ```bash
  ollama pull llama3
  ollama pull mxbai-embed-large
  ```

## Setup

```bash
# clone, then from the project root:
python3.9 -m venv venv
source venv/bin/activate

# no requirements.txt yet — install the core dependencies:
pip install fastapi uvicorn pypdf rank_bm25 chromadb ollama sentence-transformers pydantic requests
```

> Tip: freeze your environment with `pip freeze > requirements.txt` so others can reproduce it.

## Running

Make sure Ollama is running, then start the API:

```bash
uvicorn main:app --reload
```

The API is available at `http://localhost:8000`, with interactive docs at `http://localhost:8000/docs`.

## Usage

**1. Upload a PDF**

```bash
curl -X POST http://localhost:8000/greet/upload \
  -F "file=@/path/to/document.pdf"
# -> {"filename": "document.pdf", "chunks": 42}
```

> Note: each upload **replaces** the existing `documents` collection — only one document is indexed at a time.

**2. Ask a question**

```bash
curl -X POST "http://localhost:8000/greet/ask?query=what%20is%20crr"
```

```json
{
  "question": "what is crr",
  "answer": "...grounded answer based only on the document...",
  "chunks": [
    {"snippet": "...", "score": 4.21}
  ]
}
```

## Testing

After uploading a document, run the batch evaluation script (it hits `/greet/ask` with a suite of categorized questions — basics, comparisons, reasoning, noisy, out-of-context — and writes timestamped JSON results):

```bash
python test/run_test.py
```

## Notes & ideas for improvement

- Add a `requirements.txt` / `pyproject.toml` for reproducible installs.
- The BM25 index lives in memory (`bm25_store`), so it is lost on restart — re-upload to rebuild it.
- Remove debug `print` statements / commented-out experiments before production use.
- Support multiple documents / collections rather than overwriting on each upload.
